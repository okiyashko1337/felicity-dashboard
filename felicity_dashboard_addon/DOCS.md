# Felicity Energy Dashboard

Приложение локально опрашивает Wi-Fi-модуль Felicity IVGM, сохраняет историю в
`/data/felicity.db` и показывает панель внутри Home Assistant.

## Настройки

- `inverter_host`: локальный IP Wi-Fi-модуля Felicity;
- `inverter_port`: порт локального протокола, обычно `53970`;
- `poll_interval`: период показаний инвертора в секундах, по умолчанию 2;
- `system_interval`: период показаний Raspberry Pi в секундах;
- `nextion_enabled`: запуск локального UART-экрана;
- `nextion_port`: стабильный путь экрана, желательно `/dev/serial/by-id/...`;
- `nextion_baudrate`: скорость Nextion; для плавного интерфейса используется `115200`.

Экран можно подключить позже: по умолчанию `nextion_enabled: false`, поэтому
обновление приложения не меняет работу существующей панели. После прошивки
Nextion включите эту настройку, вставьте найденный в системе путь UART и
перезапустите приложение. Протокол и структура проекта редактора описаны в
каталоге `nextion` репозитория.

После запуска откройте приложение кнопкой **Open Web UI** или пунктом
**Felicity Energy** в боковой панели.

Порт приложения наружу по умолчанию не опубликован. Авторизация выполняется
Home Assistant Ingress. Никогда не пробрасывайте порт Felicity `53970` в
интернет.

Каждый запрос к локальному Wi-Fi-модулю завершается протокольным
подтверждением и аккуратным закрытием TCP-сессии. После ошибок приложение
использует экспоненциальную паузу до 60 секунд и самостоятельно возвращается к
обычному интервалу после первого успешного ответа. Это защищает модуль от
непрерывного потока повторных подключений при временном сбое.

База и её история входят в резервную копию приложения. Во время резервного
копирования приложение останавливается для согласованного снимка SQLite.

Полная телеметрия хранится только как одна текущая запись. История сохраняет
существенные поля раз в две минуты; сырые пакеты не записываются. При первом
запуске этой версии старая история автоматически прореживается, после чего
SQLite освобождает неиспользуемое место. На Raspberry Pi первый старт может
занять немного больше обычного. Точные timestamps для диагностики разрывов
хранятся отдельно три дня, системные метрики — 48 часов.
